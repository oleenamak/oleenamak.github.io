# OleenaMak.ca — skeleton

Implements concept **1b, "The Index"** from `../DESIGN-SYSTEM.md`, against
`../Brand.md`, `../Sitemap.md` and the screenshots in `../References/`.

## Live

<https://oleenamak.github.io> — GitHub Pages, from `main`, repo root.
`.nojekyll` disables Jekyll processing.

Paths are absolute (`/assets/…`), which is why the repo is named
`oleenamak.github.io` (a user site, served at the domain root) rather than a
project repo (served at `/repo-name/`, where those paths would 404). The same
holds when a custom domain is added.

### To publish a change

```bash
python3 build-pages.py && git add -A && git commit -m "..." && git push
```

Pages rebuilds automatically, roughly a minute.

### To point oleenamak.ca here

Not done yet — it would take down the existing Framer site at that address.
The domain is registered at Namecheap with DNS there; `www` currently CNAMEs to
`sites.framer.app`. When ready: add a `CNAME` file containing `oleenamak.ca`,
set the apex A records to GitHub's four Pages IPs, and CNAME `www` to
`oleenamak.github.io`.

## Run locally

```bash
python3 serve.py
```

`serve.py` is `http.server` plus no-cache headers, so edits show up on a plain
reload. Development only — never deployed. Static files, no build step, no
dependencies; must be served (not opened over `file://`) because paths are
absolute.

## Layout

```
index.html              Index template, unfiltered   (home)
writing/index.html      Index template, scope=writing
projects/index.html     Index template, scope=projects
about/index.html        Article template
assets/site.css         The whole design system
assets/entries.js       TEMPORARY content fixture + facet display order
assets/index.js         Index behaviour: facets, query header, counts, keyboard
assets/chrome.js        `/` shortcut on non-index pages
build-pages.py          Generates entry pages from entries.js
```

Three pages are hand-authored, reproducing the reference mockups verbatim:

- `writing/what-exactly-is-an-ai-operator.html` — article template
- `projects/from-positioning-to-pipeline.html` — project template
- `writing/two-people-arguing-past-each-other.html` — drawing (plate, no prose)

The other eleven are generated by `build-pages.py`, which never overwrites an
existing file. Re-run it after editing `entries.js`.

## Rules the build holds to

- Serif for anything read, mono for anything the machine knows. No third register.
- Two families, eleven colour tokens, three rule weights, one row pattern.
- `border-radius: 0`, no shadows, no gradients outside plates, no transitions,
  no animations. Verified in the DOM, not just intended.
- One grid — `190px rail + 1fr`, 40px gap — on every template. Only the rail's
  contents change.
- **Counts are computed from `entries.js`, never hardcoded.** The reference
  mockup shows a fictional `148 entries`; this build reports what exists (14).
  Facet counts are contextual: they honour the rest of the live query.
- Facet order is authored, not derived — see `TAXONOMY` in `entries.js`. The
  reference orders `ai` before `work` though `work` is the larger set.

## Content

Five pieces migrated 2026-09-09 from the live Framer site at `oleenamak.ca/writing`
(~4,200 words). Titles, decks and dates are exactly as published; slugs preserve
the old URLs so inbound links keep working.

`content.json` holds the migrated bodies and is build input, not runtime. To
update text, edit it and re-run `build-pages.py` — the body, coordinate rail and
`WHERE THIS SITS` footer all sit inside `<!-- auto:… -->` markers and are
rewritten in place. Anything outside those markers is never touched.

### Treatments derived, not specified

The reference article is a short field note — plain paragraphs and one pull
quote. The real essays needed three things §10 never defined. Each is built from
existing components; all three are one edit in `build-pages.py` + a re-run:

- **Subheads** use the uppercase mono `.label`, the system's own heading device (§1).
- **Lists** are body prose, indented, with no bullet glyph (`·` is reserved as a separator).
- **`<strong>` maps to `<em>`**, since §10 forbids bold in prose. Her bold was
  almost all list lead-ins, so the emphasis structure survives as italic.

## Known gaps

1. **Four plates have no caption** — they show only their number. The two on
   `web3-mental-models` had alt text on the old site; the four on
   `token-led-growth` and `referrals-retention-in-crypto` did not. §9 wants both.
2. **`kind` and `subjects` are a proposal.** The old site had no categories, so
   these are my reading of the pieces. One line each in `entries.js`; counts recompute.
3. **Footer, and the `elsewhere` / `contact` links, are `href="#"`.** Marked
   `TODO` in the markup. No footer is drawn in any reference; this one is built
   only from the existing sectional rule + mono row.
4. **The index list needs JavaScript.** Article and project pages are complete
   static HTML and need none. If that matters, pre-render the list at build time
   and keep the JS as enhancement.
5. **Old site has pages not migrated** — `notes` and `bookshelf` appear in the
   old nav but were not part of `/writing`.
6. **`--meta` (2.99:1) and `--faint` (2.33:1) fail WCAG AA on paper.** These are
   the specified palette values for all mono metadata. Not changed unilaterally —
   see the handover notes.
